    How to use this demo

    1. What it simulates. A subscription merchant charges 2,000 stored cards one night. Some renewals are declined. A rules engine then tries to recover them over a compressed 28-day window, where one simulated day lasts a few seconds. Every PSP, issuer, card and customer is fictional.
    2. Start a night. Press Run a night. It bills 2,000 renewals (this takes a few seconds), then starts recovery straight away. Only one night can run at a time; if another one is running, the page switches to it.
    3. Watch it run. The progress card shows how many declined renewals are settled, the simulated clock (for example Day 6 of 21), and the current phase. The live activity feed lists retries and customer messages as they happen, and the summary tiles and table update every few seconds. A night takes a few minutes.
    4. Open a payment. Select a row in Declined renewals, or a payment id in the live feed. The timeline lists every attempt, each decision the engine made, and the network rule behind it, with its source and how confident we are in that reading.
    5. Ask the assistant. The chat answers from the run's ledger using read-only tools; it never makes decisions. Try:
      • “Why did renewals fail last night?”
      • “What did you do with the expired cards?”
      • “How does this compare with the naive retry schedule?”
    6. Learn more. shows the full README with the architecture and sequence diagrams.
